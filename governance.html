Governance for AB100-HR-Agent

Project note for Exam AB-100. Governance is how we control who uses the agent, what data it may read, which systems it may call, and how we prove it later.

Exam line. Power Platform admin governs environments, connectors (DLP), and solutions. Microsoft Purview governs data and communication across Microsoft 365: labels, DLP, communication compliance, and audit. The agent still must ground on the HR file and not invent policy.

1. Three layers

Layer Where What it controls
Agent Copilot Studio Instructions (PATH A–E), knowledge file only, tool permissions, sharing / authentication
Power Platform admin admin.powerplatform.microsoft.com Environments, capacity / credits, connector DLP, solutions / ALM
Microsoft Purview purview.microsoft.com Sensitivity labels, tenant DLP, communication compliance, audit / eDiscovery, retention

2. What “governance” means on this project

  • Communication compliance — the agent must not invent HR policy or send unofficial mail as approved policy. PATH C says “I don’t know.” PATH D drafts only. PATH E sends only when asked.
  • PII security — leave dates and mail stay in allowed systems. Web search is off. Only AB100-HR-Policy.txt is knowledge. Sharing limits who can chat.
  • DLP management — Power Platform DLP allows or blocks Outlook in this environment. Purview DLP can still stop a message that leaks personal data.
  • Access — who can use, edit, and publish the agent.
  • Audit — Monitor / Evaluate in Copilot Studio; solution export for ALM; Purview Audit for tenant-wide history.

3. Power Platform admin

Area Use for this agent
Environments Dev (GlobalLogic default) vs test / prod. Do not build production in the default env if you can avoid it.
Licensing / pay-as-you-go Copilot credits. Preview and tools consume credits. Link an Azure billing plan when prepaid capacity is empty.
Data policies (DLP) Business vs non-business connectors. Outlook must be allowed with Copilot Studio or PATH E is blocked. Block HTTP / social if not needed.
Solutions AB100HRAgent package: agent, knowledge, flows, connection references. Export zip → import in another environment.

Power Platform DLP answers: may this environment call Outlook?

4. Microsoft Purview

Capability What it does HR agent example
Information Protection Sensitivity labels on files and mail Label the HR policy file Confidential
Purview DLP Stop data leaving M365 Block a leave email that includes national ID or salary
Communication Compliance Review Copilot, Teams, Outlook messages Flag abusive or off-policy HR chat
Audit / eDiscovery Who did what, and export evidence Who published the agent, who sent mail
Retention How long transcripts and mail are kept Keep or delete Preview transcripts per policy

Purview answers: may this person send that content, and can we prove it later?

5. Do not mix the two DLP names

Power Platform DLP = connectors in an environment (Outlook yes, Twitter no).

Purview DLP = content in mail, Teams, and files (detect PII, block or warn).

An agent can be allowed to use Outlook (platform DLP) and still have a specific email blocked (Purview DLP). That is expected.
